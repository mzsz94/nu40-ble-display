# NU40DK-KIT 0.1.2 실기 결과

2026-10-10, NU40은 보조배터리 전원만 연결하고 NU87은 PC USB에 연결해 검사했습니다.
NU40의 Zephyr 통합 앱은 0.1.2, NU87은 기존 AmebaD Arduino 3.1.9 기반
`firmware=3 features=smp_relay`입니다. 이번 KIT 업데이트에서 NU87 펌웨어는 바꾸지 않았습니다.

## 설치 이미지

| 항목 | 결과 |
| --- | --- |
| 업데이트 | NU87 BLE 중계로 NU40 0.1.1 → 0.1.2 |
| 서명 이미지 크기 | 208,802 bytes |
| 이미지 해시(MCUboot) | `eceeb9087be7ee227317de4537c064fb3857203226f7763b1ec26e5b5226f043` |
| 파일 SHA-256 | `c1d95d07f4136da61eae60574a353338cf83375a625c1714a899b62a3ca7a697` |
| 설치 후 primary | 대상 해시 일치, `active=true`, `confirmed=true` |
| 설치 후 secondary | 이전 0.1.1 이미지 |
| 빌드 메모리 | FLASH 208,652 bytes, RAM 133,944 bytes |

전체 전송, secondary 해시 대조, 시험 부팅 예약과 RESET 응답을 확인했습니다.
재부팅 후 같은 UART 세션에서는 SMP 조회가 `-2`로 시간 초과됐습니다. 도구가
확인 전용 UART 세션을 한 번 다시 열어 설치·확정을 확인했습니다. 재업로드나
추가 NU40 RESET은 보내지 않았습니다. 시간 초과의 근본 원인은 확정하지 않았습니다.

## 기능 검사

사용자에게 큰 키 1번 화면 전환, 2번 2초 녹음, 3번 비프, 4번 짧게 재생,
4번 0.8초 이상 RGB 모드 전환을 안내하고 OLED·RGB·비프·녹음 재생을 확인했습니다.
사용자의 응답은 **“모두 동작함”**이었습니다.

NU87을 통한 SMP 그룹 64 제어는 큐 수락 응답 이후 실제 완료 상태까지 조회했습니다.

| 항목 | 관측 |
| --- | --- |
| 키 | 준비·관측 마스크 모두 `0xf`, 네 키 입력 확인 |
| OLED | 마이크 페이지 전환 및 NU87 화면 페이지 복귀 확인, 실제 표시 사용자 확인 |
| RGB | 원격 모드 1 적용 후 0 복귀 확인, 실제 색 변화 사용자 확인 |
| 마이크 | 블록 21,626 → 22,106 증가, 읽기 오류 0 |
| 비프 | 원격 요청 완료, 누적 25 → 26, 청음 사용자 확인 |
| 녹음 | 원격 요청 완료, 32,000 samples, 누적 10 → 11 |
| 재생 | 원격 요청 완료, 누적 20 → 21, 청음 사용자 확인 |
| SD | FAT 마운트, 새 WAV 저장 후 전체 헤더·PCM 대조, 재생 전 재대조 성공 |
| SD 카운터 | 저장 10 → 11, 읽기 대조 30 → 32 |
| 작업 종료 | busy=0, mic/speaker/rgb/sd/audio 결과 모두 0 |

이번 원격 녹음의 파일은 `/KITSD:/NU40KIT/R00010.WAV`였습니다. 기존 파일을
덮어쓰지 않고 다음 빈 이름을 사용했습니다. WAV는 16 kHz/16-bit/mono, 2초,
64,044바이트입니다. 저장 후 RAM과 파일을 대조했으며 카드 전체 무결성 검사는 아닙니다.

첫 기능 검사에서는 초기 상태 조회가 `-2`로 실패해 동작 명령을 보내지 않았습니다.
후속 조회는 성공했고, 상태 읽기만 최대 3회 시도하도록 호스트 도구를 보완했습니다.
이어진 원격 기능 검사는 모두 완료했습니다. 녹음·재생 같은 쓰기는 자동 반복하지 않습니다.

## 소프트웨어 검사

- NU40 저장소의 Python 검사 171개 통과. 실제 공유 C 로직은 ASan/UBSan으로 실행했습니다.
- 버튼 독립 디바운스·긴 누름·32-bit 시간 wrap, WAV 손상·크기 경계,
  SMP 단편화·응답 매칭, 서명·복구 영역 경계, 작업 완료 판정을 검사했습니다.
- Twister `nucode_nu40/nrf52840` build-only 시나리오 1개 통과, 빌드 경고 없음.
  Twister에서 보드 런타임 시나리오를 실행한 것은 아닙니다.
- NU87 배포 폴더의 호스트 검사 102개, 광고 필터 검사 1개와 C++ ACK gate 검사 통과.
  공개한 7개 런타임 소스의 해시를 설치된 NU87 이미지의 빌드 manifest와 대조했습니다.

재현 명령은 [앱 안내](../nu40_ble_display/README.md)와
[NU87 중계 안내](https://github.com/mzsz94/micro-wallaby/tree/feat/nu87-nu40-kit-ota/firmware/nu87_nu40_bridge)에 있습니다.

## 범위와 원본 기록

녹음 재생은 현재 부팅의 마지막 2초 버퍼를 사용합니다. 기존 WAV 선택 재생,
사용 중 카드 교체, 음성 인식, 정량 음질 측정은 구현·검증 범위에 포함하지 않았습니다.
장시간 안정성, OTA 전원 차단과 실제 롤백은 별도 검사 대상입니다.
서명 검증은 펌웨어 설치를 보호하지만 BLE 연결 자체의 인증·암호화를 추가한 것은 아닙니다.

작업 PC의 다음 경로에 원본 성공·실패 기록을 함께 보관했습니다. Git에는 원본 연속 로그,
이미지 바이너리와 개인 서명 키를 포함하지 않습니다.

- `build/kit-history/integrated-ota-20261010-222049/`: 설치 전 소스·설정·이미지 해시
- `build/kit-history/ota-0.1.2/`: 전체 전송·첫 세션 시간 초과·새 세션 확정 조회
- `build/kit-history/initial-status-0.1.2/`: 최초 KIT 상태
- `build/kit-history/functional-0.1.2/`: 초기 읽기 시간 초과 원본
- `build/kit-history/status-retry-0.1.2/`: 후속 상태 조회
- `build/kit-history/functional-retry-0.1.2/`: 원격 기능별 전후 상태와 완료
- `build/kit-history/manual-observation-0.1.2.json`: 사용자 실제 동작 확인
